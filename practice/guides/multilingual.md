# Многоязычность в проекте: как устроена и как поддерживать

Этот документ описывает текущую мультиязычную конфигурацию сайта и правила сопровождения с точки зрения разработчика. Формулировки нейтральные, без привязки к конкретному человеку.

## 1. Общая схема

В проекте используется двухъязычная структура (RU/EN). Логика следующая:

- Конфигурация языков задаётся в `config.toml` в секции `[languages]`.
- Для каждого языка определён свой `contentDir`.
- Включён режим `defaultContentLanguageInSubdir = true`, поэтому **даже язык по умолчанию** получает префикс (`/ru/`).
- Структура каталогов в `content/ru` и `content/en` зеркальная.

## 2. Ключевые параметры в `config.toml`

```toml
languageCode = "ru"
defaultContentLanguage = "ru"
defaultContentLanguageInSubdir = true

[languages]
  [languages.ru]
    contentDir = "content/ru"
  [languages.en]
    contentDir = "content/en"
```

Дополнительно в каждом языке определены:

- `title` и `languageName`
- `menu.main` (верхнее меню)
- `params` (локализованные тексты для header/footer/CTA)

Это означает, что все текстовые элементы шапки/футера должны храниться в `languages.<lang>.params`, а не в общем `[params]`.

## 3. Структура контента

Контент размечен по одинаковым путям:

```
content/
  ru/
    _index.md
    about.md
    contact.md
    docs/
      _index.md
      web/
      design/
      research/
  en/
    _index.md
    about.md
    contact.md
    docs/
      _index.md
      web/
      design/
      research/
```

Такая симметрия нужна для корректного связывания переводов и единообразной навигации.

## 4. URL и префиксы

Поскольку включён `defaultContentLanguageInSubdir`, итоговые URL выглядят так:

- Русская версия: `/ru/...`
- Английская версия: `/en/...`

Это касается и главной, и разделов, и отдельных работ.

## 5. Навигация и меню

Верхнее меню (Home/About/Contact) задаётся отдельно для каждого языка в `languages.<lang>.menu.main`. Это позволяет:

- использовать разные подписи (`Главная` vs `Home`),
- корректно указывать URL с префиксом языка (`/ru/about/` и `/en/about/`).

Левое дерево (sidebar) строится темой Hugo Book из секции `docs` в соответствующей языковой папке. Это значит, что **структура `content/<lang>/docs` определяет боковую навигацию**.

## 6. Как добавлять новые страницы

Правило для разработчика:

1. Создать страницу **в обоих языках** по одинаковому пути.
2. Убедиться, что в обоих языках есть `_index.md` для разделов.
3. При необходимости обновить меню каждого языка.

Пример:

```
content/ru/docs/web/project-new.md
content/en/docs/web/project-new.md
```

## 7. Как добавлять новый язык

Короткий чек‑лист:

1. Добавить новый блок в `[languages]`:
   - `contentDir`, `title`, `languageName`, `weight`.
2. Создать новую папку `content/<lang>` с зеркальной структурой.
3. Скопировать меню и локализовать подписи.
4. Добавить локализованные параметры в `languages.<lang>.params`.

## 8. Типичные ошибки

- Создана страница только в одном языке — перевод не связывается, меню выглядит неполным.
- Неправильный URL в `menu.main` (без языкового префикса) — ведёт на неправильную версию сайта.
- Разная структура каталогов в RU и EN — приводит к разным деревьям в боковом меню.

## 9. Связанные файлы

- `config.toml` — языковые настройки, меню, параметры.
- `content/ru/` и `content/en/` — контент по языкам.
- `layouts/` — шаблоны, не зависят от языка (данные приходят из `Site.Language`).
