# Hugo: полный учебник по созданию и ведению сайта

Это руководство объясняет, как работать с Hugo в учебном проекте. Материал основан на официальной документации Hugo и адаптирован под структуру текущего репозитория.

## 1. Что такое Hugo и как он работает

Hugo — генератор статических сайтов. Вы пишете контент в Markdown, задаете конфигурацию, а Hugo собирает готовый HTML‑сайт. Такой подход дает скорость, простоту деплоя и предсказуемое поведение. Основные команды Hugo:

```bash
hugo version
hugo new site <site>
hugo server
hugo
```

Команда `hugo server` поднимает локальный сервер, а `hugo` собирает статический сайт в папку `public/`.

## 2. Структура проекта и базовые папки

Hugo строит сайт на основе папок и конфигурации. Базовые директории:

- `content/` — страницы, посты и разделы.
- `layouts/` — шаблоны отображения.
- `static/` — файлы, которые копируются в сборку без обработки.
- `assets/` — исходники, которые могут обрабатываться пайплайном (например, SCSS).
- `archetypes/` — шаблоны для команды `hugo new`.

В этом репозитории ключевой контент лежит в `content/ru` и `content/en` (мультиязычный сайт), а основной раздел с работами находится в `content/*/docs`.

## 3. Конфигурация: hugo.toml, baseURL и параметры

Hugo поддерживает конфиг в форматах TOML/YAML/JSON. В проекте используется `config.toml`. Важные параметры:

- `baseURL` — адрес сайта, от него зависит генерация ссылок.
- `languageCode` и `defaultContentLanguage` — настройки языка по умолчанию.
- `theme` — подключаемая тема.

Пример ключевых параметров:

```toml
baseURL = "https://example.org/"
title = "Портфолио"
theme = "hugo-book"
languageCode = "ru"
defaultContentLanguage = "ru"
defaultContentLanguageInSubdir = true
```

## 4. Организация контента: секции и URL

Hugo рассматривает папки внутри `content/` как секции. Каждая секция формирует дерево страниц и URL‑адресов. Например:

```
content/ru/docs/web/project-landing.md
```

даст страницу с URL внутри русской версии и в секции `docs/web`.

Для разделов часто создают `_index.md`. Это файл, который задает заголовок и описание секции. Без `_index.md` секция будет работать, но вы потеряете контроль над заголовком и порядком в меню.

## 5. Page Bundles (наборы страниц)

Hugo поддерживает логическую группировку контента — page bundles. Это помогает хранить изображения и данные рядом со страницей. Типичный шаблон:

```
content/ru/docs/web/project-landing/
  index.md
  cover.png
  gallery/
```

Такой подход удобен для портфолио‑проектов: все материалы лежат рядом с описанием работы.

## 6. Archetypes и ускорение создания контента

Archetypes — это шаблоны фронт‑маттера. Они определяют поля по умолчанию для новых страниц. Например, можно заранее задать теги, структуру summary и блок links.

Создание нового материала:

```bash
hugo new docs/web/my-project.md
```

Hugo применит шаблон из `archetypes/default.md`. Это снижает количество ручной работы и делает контент единообразным.

## 7. Мультиязычность

Hugo умеет хранить разные языковые версии контента. В проекте используются две директории:

- `content/ru` — русская версия
- `content/en` — английская версия

В конфиге для каждого языка задается `contentDir` и параметры меню. Это позволяет держать структуру синхронной между языками.

## 8. Меню и навигация

Меню можно задавать двумя способами:

1. Через конфиг (секция `menu` в `config.toml`).
2. Через фронт‑маттер в файлах контента.

В этом репозитории верхнее меню задается в конфиге, а левое древовидное меню формируется темой Hugo Book на основе секции `docs`.

## 9. Практика для этого репозитория

Ключевые моменты:

- Основной контент находится в `content/ru` и `content/en`.
- Работы портфолио лежат в `content/*/docs`, чтобы Hugo Book строил левое дерево.
- Разделы портфолио оформляются через `_index.md` и отдельные страницы работ.
- В каждом проекте есть поля `summary`, `tags`, `links`, чтобы легко показывать суть работы.

Пример структуры:

```
content/
  ru/
    docs/
      web/
        _index.md
        project-landing.md
```

## 10. Частые ошибки и чек‑лист запуска

Частые ошибки:

- Неверный `baseURL` — ссылки становятся некорректными.
- Отсутствует `_index.md` в разделе — меню и заголовки могут выглядеть неожиданно.
- Контент в draft — страницы не публикуются.

Чек‑лист:

1. `hugo version` показывает `+extended`.
2. `hugo server` запускается без ошибок.
3. `hugo` успешно строит сайт.
4. В меню слева видны разделы и проекты.
